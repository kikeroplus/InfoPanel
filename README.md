# InfoPanel

ESP32-S3 と 240x320 の液晶で作る情報表示端末。WorkingTimer とは別の端末で、タイマーより情報表示が主。

## 機種

同じプログラムで 2 つの機種を動かす。画面・MQTT・操作は共通で、違うのは液晶の設定と音だけ。

| | buzzer (初号機) | speaker |
|---|---|---|
| 液晶 | ST7789 240x320、BL 端子あり (GPIO7)、色反転 false | ST7789 240x320 (`..\TFT-Tester-ESP32S3-240-320-A` のもの)、BL 端子なし、色反転 true |
| 音 | パッシブブザー (GPIO6) | MAX98357A + スピーカー (I2S 15/16/17)。チャイムの音を合成し、呼び出しのときだけしゃべる |
| スイッチ | SW1〜4 (13, 14, 1, 2) | SW1〜3 (13, 14, 1) |
| 明るさ (SW1 長押し) | 変えられる | 変えられない (BL がない) |

どちらも ESP32-S3-DevKitC-1 N16R8 (Flash 16MB / PSRAM 8MB Octal)、横置き 320x240。

### 書き込むとき

機種を env で選ぶ。違う機種のものを書くと、色が反転したり音が出なかったりする (壊れはしない)。

```
pio run -e buzzer -t upload     (初号機)
pio run -e speaker -t upload    (スピーカーの機体)
pio run                         (両方をビルドするだけ。直したら両方通ることを確かめる)
```

VS Code では下のバーの env の切り替え (`env:buzzer` / `env:speaker`) で選んでから書き込む。

### 2 機種で食い違わないための決まり

- 機種で違うもの (ピン、液晶の反転・向き、BL、スイッチの数、音の出し方) は **`include/board.h` だけ**に書く。`main.cpp` に GPIO の番号を書かない
- `main.cpp` で機種を分けるのは、機能の有無 (`#if TFT_BL >= 0` など) で分けるところだけ。機種の名前 (`BOARD_SPEAKER`) で分けない
- 音は `src/sound.h` の `Sound` (何の音か) で鳴らす。音を足すときは `Sound` に名前を足し、`sound_buzzer.cpp` と `sound_speaker.cpp` の両方に鳴らし方を書く (speaker は数が合わないとビルドが止まる。buzzer は書き忘れると鳴らないだけ)
- しゃべるのは `soundSay()`。ブザーの機体では何もしないので、呼ぶ側で機種を分けなくてよい
- `src/kanavoice.h` / `kanavoice.cpp` は `..\SpeechTest\src` からそのまま写したもの。ここでは直さず、SpeechTest で直してから写し直す
- 直したら `pio run` で両方の env がビルドできることを確かめる

## 配線

液晶とスイッチ 1〜3 は 2 機種で同じ。BL・スイッチ 4・ブザーは buzzer だけ、アンプは speaker だけ。

| 液晶 | S3 の GPIO | 備考 |
|---|---|---|
| VCC | 3.3V | |
| GND | GND | |
| SCL (SCK) | 12 | |
| SDA (MOSI) | 11 | |
| CS | 10 | |
| DC | 9 | |
| RST | 8 | |
| BL | 7 | buzzer だけ (speaker の液晶には BL 端子がない) |
| SDO (MISO) | 未接続 | |

| 部品 | S3 の GPIO | 備考 |
|---|---|---|
| スイッチ 1 | 13 | もう片側は GND。内部プルアップで押すと LOW |
| スイッチ 2 | 14 | 同上 |
| スイッチ 3 | 1 | 同上。将来の拡張用 (まだ役割なし) |
| スイッチ 4 | 2 | buzzer だけ。同上 |
| ブザー | 6 | buzzer だけ。パッシブタイプ。PWM (LEDC チャンネル 0) で鳴らし、デューティ比で音量を変える。トランジスタで駆動 (下の回路) |

| MAX98357A (speaker だけ) | S3 の GPIO | 備考 |
|---|---|---|
| BCLK | 15 | |
| LRC | 16 | |
| DIN | 17 | |
| Vin | 5V | 3.3V でも鳴るが小さい |
| GND | GND | |
| SD・GAIN | 未接続 | 左右を混ぜて鳴らす、9dB |

GPIO13 は SPI2 の MISO の決まったピンなので、スイッチの `pinMode` は液晶の `begin` のあとでする (先にすると押していなくても LOW になることがある)。

### ブザー回路

![ブザー回路](docs/buzzer-circuit.png)

- GPIO6 → 1kΩ → 2SC1815 のベース (B)。エミッタ (E) は GND。
- コレクタ (C) → ブザーの −。ブザーの + → 3.3V。
- 1N4148 をブザーと並列に、カソード (帯の側) を 3.3V 側にして入れる (コイルの逆起電力からトランジスタを守る)。
- パッシブの電磁ブザーはコイルの抵抗が小さく (16〜42Ω ほど)、GPIO から直接だと電流が多すぎるのでトランジスタを通す。
- 図の「GPT06」は GPIO6 のこと。

- S3 には GPIO23 がないため、テスト時 (ESP32: SCK18 MOSI23 CS5 DC16 RST17 BL4) とはピンが違う。
- 使わないピン: 0・3・45・46 (起動モード)、19・20 (USB)、35〜37 (Octal PSRAM が使う)、43・44 (シリアル)。

## 画面と操作

| ページ | 内容 |
|---|---|
| 01 OVERVIEW | 7 セグの時計・日付、3 台のカード (状態・ComfyUI・GPU/CPU/RAM/VRAM)、最新の出来事、今日のまとめ |
| 02 SYSTEMS | 3 台の CPU・GPU・RAM・VRAM の棒と温度 |
| 03 RENDER | ComfyUI の状態、ノード、ステップの進み、経過、速さ (s/it)、ノードの残り時間、今日のジョブ数と稼働時間 |
| 04 TRENDS | GPU 使用率と GPU 温度の 12 分間のグラフ |
| 05 SCOPE | レーダー表示 (中心から遠いほど GPU が忙しい) |
| 06 EVENTS | 出来事の記録 (接続・切断、ジョブの開始と終了、エラー、呼び出し) |
| 07 DEVICE | WiFi・MQTT・メモリなどこの端末の状態、操作の説明 |
| 08 GRAY | 液晶の残像を消すための全面表示 (上の帯も出さない)。SW1 長押しでグレー → 白 → 黒 → AUTO (10 秒ずつ順に) |

| 操作 | 動き |
|---|---|
| SW1 | 次のページ |
| SW2 | 前のページ |
| SW1 長押し (0.7 秒) | 明るさ (HIGH / MID / LOW。buzzer だけ)。08 GRAY では色の切り替え |
| SW2 長押し | 音量 (HIGH → MID → LOW → OFF の順に回る) |
| アラート中にどちらか | アラートを閉じる |

- アラート (画面中央に点滅、警告音): PC の予期せぬ切断 (`lost`)、ComfyUI の `error` / `down` / `stalled`、呼び出しベル (`doorbell/call/+` の `ON`)。正常に戻ると自動で閉じる。
- 呼び出しは ON から 20 秒は CALL を出し続け、その間 5 秒ごとに呼び出し音を鳴らす (`OFF` がすぐ来ても 20 秒は閉じない。20 秒たっても `OFF` が来なければ、来るまで出したまま音は止める)。長さは `main.cpp` の `CALL_HOLD_MS`・`CALL_REPEAT_MS`。どれかのスイッチを押せばすぐ閉じる。
- ジョブが終わると短いチャイムと画面上の通知 (上の帯に 4 秒重ねる)。
- 音量は LOW で起動する。

### 音 (speaker)

ブザーと同じ場面で鳴らすが、スピーカーなので音を合成して鳴らす (`src/sound_speaker.cpp`)。

| 場面 | 音 |
|---|---|
| 起動 | ドミソド と上がるチャイム |
| ジョブ完了 | 高いミソド の きらっとした音 |
| アラート (切断・ComfyUI の異常) | 高低の警告音を 3 回 |
| 呼び出しベル | ピン・ポーン のあとに「よびだされました」としゃべる (20 秒の間 5 秒ごとにくり返す) |
| スイッチ | 短い ちっ という音 |
| 音量を変えたとき | 新しい音量で 2 音 |

- しゃべるのは呼び出しのときだけ。声は kanavoice の「ふつう」(130Hz。`sound_speaker.cpp` の `VOICE`)
- 大きさは `include/board.h` の `TONE_VOLUME` (音) と `VOICE_VOLUME` (声)。SW2 長押しの音量 (HIGH / MID / LOW / OFF) はこれに掛かる
- 今日のジョブ数・稼働時間は端末が起動してから数えたもので、日付が変わると 0 に戻る。

## 書き込み

- 基板の USB 端子は 2 つある。書き込みとシリアルモニタは「COM」(UART) 側を使う。
- COM 番号が決まったら `platformio.ini` のその機種の env に `upload_port` を書く。

## WiFi の設定

SSID とパスワードはファームウェアに書かず、起動時の設定ポータル (WiFiManager) で決める。仕組みは WorkingTimer と同じで、`include/WiFiSetup.h` は WorkingTimer と同じファイル (直すときは両方を揃える)。

1. 保存済みの WiFi につながらないと (書き込み直後など)、画面が「WIFI SETUP MODE」になり、AP `InfoPanel-XXXX` (MAC の末尾 4 桁) が立つ。
2. スマホでその AP につなぎ、設定ページ (開かなければ `192.168.4.1`) で SSID・パスワードを選んで保存する。同じページで「Device name」(任意) と「MQTT server」(初期値 `192.168.11.32`、空欄なら MQTT を使わない) も変えられる。
3. 保存すると再起動なしでつながり、いつもの画面になる。次からは自動でつながる。
4. 別の WiFi に変えたいときは **SW1 を押しながら起動 (リセット)** すると、保存済みの WiFi を消して設定モードになる。
5. 3 分たっても設定しなければ設定モードを終えてオフラインで動く (保存済みの WiFi があれば 30 秒ごとにつなぎ直す)。

ESP32 は 2.4GHz にしかつながらない。設定ページの一覧に 5GHz の SSID が出ないのは正常。
